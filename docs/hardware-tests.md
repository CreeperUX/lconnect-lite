# 硬件实测记录

硬件：隐流二代 LCD-S（USB）+ UNI FAN TL 无线 × 3 + L-Wireless V1 收发器。

## 2026-10-21 · 无线模式控泵修复

**原因**：官方在无线模式下只用参数块（RF 0x21，每秒一次）里的泵定时器控泵，并且不给不带无线风扇的冷头发 PWM 帧
（`MasterDevice.NeedSyncPwm`：风扇数为 0 直接跳过）。我们每秒往 PWM 帧第 4 路发泵占空比，冷头把它也当泵速执行，
两个来源轮流生效。按 2238 rpm 算出的占空比约 40%，冷头执行下来约 1880 rpm，正好是之前测到的低点。

**修改**：无线模式下不给冷头发 PWM 帧（带无线风扇的 CL 版只改三路风扇，泵那一路回填设备当前值）；参数块 [16]
和官方一样留 0。0x19 是“把冷头屏幕切到无线主题”（`SwitchAioLcdWirelessMode`），和泵无关；我们的屏幕走 USB，故意不发。

**复测**（绑定 → 阶跃 → 解绑，每 2 s 一个读数）：

| 阶段 | 目标 | 泵速 |
|---|---|---|
| USB 基线 | 2271 | 2370–2386 |
| 绑定（从 rx 0 开始，6.6 s 收敛） | 2264 | 先降到约 2088 停约 8 s（USB 切到无线的过渡），然后 2342–2361 |
| 固定 2800 | 2800 | 约 12 s 后跳到 2853–2913，**之后稳定** |
| 固定 2000 | 2000 | 约 14 s 后降到 2080–2097，稳定 |
| 恢复原配置 | 2249 | 约 12 s 后 2345–2353，稳定 |
| 解绑（1.1 s）后 USB | 2254 | 2283–2369 |

结论：无线模式下泵速不再来回跳，阶跃响应约 12–14 s（和 USB 模式相同），稳态比目标高 80–100 rpm（映射表本身的偏差，和 USB 模式一致）。
从 rx 0 重新绑定也正常。

## 2026-10-21 · 无线绑定（冷头 LCD-S 的无线模块 60:99:d8:e5:66:e1）

按 [porting/binding.md](porting/binding.md) 的计划。绑定前：未绑定、rx 254、频道 8；TL 组占 rx 3。

| 步骤 | 结果 |
|---|---|
| 第 1 次绑定 | 被前置检查拒绝：只看一轮 RX 回复，冷头恰好没被报告。改为最多 5 轮 + 3 秒内的缓存 |
| 第 2、3 次绑定 | 5 秒未收敛，没有保存，设备保持原状。第 3 次改成按设备当前 rx（254）和 0xFF 两种方式发 |
| 第 4 次绑定 | **成功**，6.2 秒收敛，rx 1，已保存。修正：绑定帧里的 PWM 原来用设备报告的值（冷头为全 0），改成官方给新设备的默认 100 |
| 无线模式下 RF 控泵 | 能跟随但不平稳：目标 2800 时在 2094–2338 间跳，约 24 s 到 2887；恢复后一度掉到约 1880 |
| TL 组主板灯光同步 | 开启未被确认（10 次重发），可能因为接收器没接 ARGB 同步线；未验证 |
| 解绑 | **成功**，1.4 秒收敛，主机清零、rx 0；后台服务自动回到 USB 控泵，泵速平稳 |
| 屏幕 | 全程正常显示仪表盘 |

### 结论与待办

1. **绑定帧的 PWM 不能是 0**：冷头的第 4 路是泵，发 0 时冷头不接受绑定，泵还会短暂减速（测到过 1874 rpm）。已修。
2. **无线模式的控泵不平稳**：已修，见上一节。
3. 解绑后 rx 是 0 而不是出厂时的 254；从 rx 0 再绑定已验证正常。没有做冷头断电重启后的保存验证。

## 2026-10-21 · 灯效与屏幕

| 项目 | 结果 |
|---|---|
| TL 风扇静态色上传 | 2 个 RF 包，约 0.9 s 后 GetDev 里的 effect_index 与计算值一致 |
| 冷头灯圈 0xFC 推送 | 推送 + 重开设备 + GetVer 恢复约 1 s；冷头随后泵速回到固件默认约 2080 rpm，重发 0xFB 后约 7 s 回到目标 |
| 屏幕仪表盘 / 图片（旋转 90°）/ GIF（24 帧） | 都推送成功；GIF 连续播放 30 s，0xFA/0xFB 控制零错误 |
| 后台服务内存 | 不用 GPU 读数时私有约 2.6 MB；仪表盘模式（加载 NVML）约 22.7 MB |

### 发现并修复的问题

1. **重开 USB 被拒绝**：推送灯圈后重开设备时旧句柄还没关，WinUSB 独占导致“拒绝访问”。改为先彻底关闭再打开（最多重试 5 次）。
2. **冷头会插入零长度包**：读到 0 字节原本被当成超时，导致 JPEG 确认包和 0xFA 回复被漏掉、GIF 播放时读不到水温、
   有一帧只写进去 9216/10037 字节。改为读到 0 字节继续等到截止时间。诊断程序：`examples/lcd_probe.rs`。
3. **libusb 超时 0 表示无限等待**：剩余时间不足 1 ms 时会卡死。USB 层统一把超时下限设为 1 ms。
4. **NVML 卸不掉**：nvml.dll 加载后 drop 也不释放（约 20 MB）。改为只在控制或仪表盘需要时由后台服务加载，
   界面显示用的 GPU 读数由界面进程自己读。
5. **字体占内存**：微软雅黑 19 MB 整个读进堆，改为内存映射。

## 2026-10-21 · 后台服务曲线控制

方法：停掉 L-Connect 服务，`lcl-daemon serve` 接真实硬件，脚本经命名管道每秒读一次状态，
按 均衡（25 s）→ 性能（25 s）→ 固定 30% / 2000 rpm（25 s）→ 均衡（20 s）切换配置。

| 项目 | 结果 |
|---|---|
| 曲线查表 | 正确：水温 26/27 °C → 均衡 33/36%、2240/2280 rpm；性能 48/51%、2840/2880 rpm |
| 风扇限速 | 正确：按 5%/s 爬升和下降（33→38→43→48、48→43→38→33→30） |
| 风扇转速 | 30% ≈ 740 rpm，36% ≈ 880–900 rpm，48–51% ≈ 1230 rpm，60% ≈ 1500 rpm；转速变化约 6 s 到位 |
| 泵 | 约 12–15 s 到位，实际比目标高 40–120 rpm（映射表本身的偏差） |
| 错误 | 95 s 内无 |
| 后台服务内存 | 7.9 MB（接硬件） |

### 发现的问题

1. **水温只有整数精度**，在 26/27 之间来回跳，风扇目标随之在 33/36% 间抖动（PWM 84/92）。
   已修：水温加 20 s 时间常数的一阶低通。复测时原始值 26↔27，滤波后稳定在 26.9，
   风扇指令 35.7–35.9%，PWM 91/92。
2. **从 L-Connect 接管后的前 25 s，风扇转速读数停在 1315 rpm 不变**，而 RX 报告的 PWM 已经是 92。
   之后切换配置时转速正常变化。用调试命令先设 60% 再启动后台服务复测，**没有复现**
   （约 6 s 从 1530 降到 900）。怀疑和 L-Connect 停止前留下的状态有关，待下次从 L-Connect 交接时再观察。
