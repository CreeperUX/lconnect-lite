# 无线设备管理：移植方案

来源：lian-li-linux（LLL，`crates/lianli-devices/src/wireless/`）与反编译的 L-Connect 3（VND，`lianli.slv3/slv3/`，只作参考）。

## 1. 绑定 / 解绑

- **绑定帧**（240 B，RF 0x10）：`[0]=0x12 [1]=0x10 [2..8]=设备 MAC [8..14]=目标主机 MAC [14]=目标 rx [15]=我们的频道 [16]=slot [17..21]=设备当前 PWM`，其余为 0（LLL bind.rs:348-365，测试向量 bind.rs:452-455）。
- **slot**：在 RX 列表顺序里、属于我们的设备中排第几（从 1 开始，跳过类型 0xFF）；还不在列表里就是数量 + 1。解绑时为 0。
- **空闲 rx（1..13）**：取第一个没被我们要保留的设备占用的 rx（LLL bind.rs:285-299）。
- **发送**：RF 头里 rx 目标用 0xFF 广播，由帧内 MAC 选设备；频道用设备报告的频道（报 0 则用我们的）。每轮 6 帧，间隔 30 ms。
- **确认**：每轮发完等 150 ms 再 GetDev，要求晚于发送时间的记录显示 master==我们、rx==目标、频道==我们；5 s 超时。解绑只要求 master 和 rx 都为 0。
- **保存配置 RF 0x15**：`[0]=0x12 [1]=0x15 [2..8]=FF×6 [8..14]=我们的 MAC [14]=0xFF`，在我们的频道上以 rx 0xFF 发 3 次，间隔 200 ms。只在确认收敛之后发。
- **防护**：设备离线、或者它的 master 是另一个在线的发射器时拒绝；上限 10 个设备、1 个 LCD-S。
- **坑**：
  - 别的发射器在 RX 列表里是类型 0xFF 的记录，我们现在的 `parse_record` 把它们丢了，做“对方在线”判断之前要先保留下来。
  - 设备可能把旧时钟广播里的传感器字节当成频道/rx（比如频道 45 或 0），记录仍然说明设备在线；有效范围是 rx 1..13、频道 1..39。恢复办法：用 0xFF 重发绑定帧。
  - L-Connect 会自动解绑“报我们 MAC 但它不认为已绑定”的设备，两个软件同时运行会互相抢绑定。
  - 不要照搬 LLL 的自动重新绑定，手动解绑必须保持解绑状态。

## 2. 切换频道

- 官方只允许手动选奇数频道；偶数频道留给多个发射器自动避让（按 MAC 排序，取 8+4·i）。
- 切换只改主机这边的频道和已绑定设备的目标频道，之后在设备旧频道上重发绑定帧（同 rx、新 [15]）。官方把频道存在主机端配置里，启动时读回。
- 风险最高的操作：漏掉重发帧的设备会留在旧频道。我们的发现流程从 8 开始扫，不在主机端记住频道的话，重启后时钟广播可能发不到它们。放到最后做。
- 已实现（`Wireless::change_channel`）：先确认 TX 在新频道上应答 GetMac；逐个本机设备在它当前频道上重发绑定帧（同 rx、同 slot、[15]=新频道），等 RX 报告它到了新频道；全部到位后在新频道上发保存（RF 0x15）。有设备 5 s 内没确认：不等确认，对每个设备在新频道上发“回到原频道”的绑定帧，再到原频道上确认，最后保存。主机频道记在 `config.toml` 的 `devices.channel`，后台服务连上发射器时换过去一次。
- 实测：RX 同时能听到不同频道上的设备（切到 9 后仍报告频道 8 上未绑定的冷头无线模块），所以掉队的设备一般还能找回来。

## 3. 主板同步

- **主板灯光同步 RF 0x27**：`[2..8]=设备 [8..14]=主机 [14]=rx [15]=频道 [16]=slot（从 0 开始） [17]=新 cmd_seq [20]=1 开 / 0 关`。最多重发 10 次，直到记录的 cmd_seq（[40]）等于目标；[28] 的 0x40 位表示同步已开启。TL V2（类型 27-35）和 LCD-S 都支持。
- **硬件 PWM 同步（PWM 值 6）**：只有 SL V3（风扇类型 20-26）支持，**你的 TL 风扇不支持**，所以跟随主板只能在软件里做：读 RX 头里的主板 PWM，再按普通 PWM 下发（我们已经这么实现了）。
- 注意：官方会给 MAC 以 e1 结尾的设备发 6，**你的 LCD-S（60:99:d8:e5:66:e1）正好以 e1 结尾**，绝不能误发 6 给它（我们的 `constrain_pwm` 已经把 6 改成 7）。
- RX 测主板 PWM 需要把主板风扇口的 PWM 线接到接收器上（从 RX 回复格式推断，没找到官方说明）。

## 4. 锁定绑定

纯主机端：把当前属于我们的设备 MAC 存成列表；锁定期间不接收新设备、不清理离线设备。我们这边约 30 行：一个允许的 MAC 列表，用来过滤 `own_devices`。

## 5. 我们要加的（约 260 行）

1. `parse_record` 保留类型 0xFF 记录到 `Snapshot.masters`，并保留 cmd_seq 和状态位。
2. `bind_frame` + `converge(mac, master, rx, deadline)`。
3. `bind(mac)`：前置检查 → 选空闲 rx → 收敛 → SaveConfig。
4. `unbind(mac)`、`save_config()`。
5. `set_mb_light_sync(dev, slot0, on)`。
6. `switch_aio_wireless(dev, slot)`（RF 0x19）+ `set_aio_params`，把冷头切到无线控制。
7. 切换频道放最后。

## 硬件测试计划（先关 L-Connect）

1. 先 dry-run，核对 LCD-S 的绑定帧十六进制。
2. 绑定 LCD-S：TL 组占了 rx 3，预期分到空闲 rx；5 s 内 RX 列表应显示 master=我们。然后 SaveConfig，冷头断电重启再确认。
3. 切冷头到无线模式，确认泵速跟随 RF 参数。
4. 对 TL 组开关 0x27，看 [28] 的 0x40 位和 cmd_seq。
5. 解绑 LCD-S，确认 master 归零，再重新绑定。

## 实测补充（2026-10-21）

- **发帧地址**：每轮先按设备当前的 rx 发（官方做法；未绑定的冷头无线模块报 rx 254），再以 0xFF 广播。
- **PWM 字段不能是 0**：设备报告的 PWM 全 0 时用官方给新设备的默认值 100。冷头的第 4 路是泵，发 0 时冷头不接受绑定，泵还会减速。
- **冷头无线模式下不发 PWM 帧**：泵只由参数块控制（官方 `NeedSyncPwm` 对风扇数为 0 的设备直接跳过）。
- **不发 0x19**：它会把冷头屏幕切到无线主题；我们的屏幕走 USB。
- 绑定约 6 s、解绑约 1 s 收敛；从 rx 254 和 rx 0 绑定都验证过。

## 恢复办法

- 设备卡在“master 是我们但 rx/频道不对”：在设备报告的频道上用 rx 0xFF 重发绑定帧，或先解绑再绑定；L-Connect 的绑定功能也能恢复。
- 永远不要复用 TL 组正在用的 rx；没确认收敛前不要发 SaveConfig。
